MaxDiff Analysis of MSBA Class Preferences

Counts, MLE, and Bayesian estimation of the MNL model

Author

Peirong

Published

June 10, 2026

1 Introduction

MaxDiff, also called Best-Worst Scaling, is a survey method for measuring relative preferences. Instead of asking respondents to rate each item on a numeric scale, the survey repeatedly shows a small set of items and asks for the most preferred and least preferred option. In this assignment, each real MaxDiff task shows 4 MSBA core classes.

MaxDiff is useful because people are usually better at making trade-offs than at calibrating a 1 to 10 rating scale. Two students might both say a class is an 8, but mean very different things. Asking them to choose the best and worst class from the same set forces clearer differentiation.

Here I estimate class preferences using three approaches. First, I compute a simple counts score: percent picked best minus percent picked worst. Second, I fit a multinomial logit (MNL) model by maximum likelihood. Third, I fit the same MNL model with a Bayesian random-walk Metropolis sampler. I expect all three methods to agree most clearly on the top and bottom classes, with more disagreement among middle-ranked classes where preferences are closer together.

3 Counts Analysis

The counts analysis is the simplest way to summarize the MaxDiff data. For each class, I calculate the percentage of times it was chosen as best and subtract the percentage of times it was chosen as worst:

\[ \text{score}_j = \%\text{best}_j - \%\text{worst}_j. \]

A positive score means the class is more often selected as best than worst. A negative score means the opposite.

score_from_data <- function(dat) {
  dat |>
    group_by(Item) |>
    summarize(
      shown = n(),
      best = sum(Response == 1),
      worst = sum(Response == -1),

      .groups = "drop"
    )
}

4 From MaxDiff Data to MNL Choices

For the MNL model, each task is treated as two linked choice observations. First, the respondent chooses the best class from the four shown items. If the shown set is \(\{a, b, c, d\}\), the probability that class \(b\) is selected as best is

\[ P(\text{best} = b) = \frac{\exp(\beta_b)} {\exp(\beta_a) + \exp(\beta_b) + \exp(\beta_c) + \exp(\beta_d)}. \]

Then the respondent chooses the worst class from the remaining three. For the worst choice, the utilities are flipped, so lower-utility classes become more likely to be selected:

\[ P(\text{worst} = c \mid \text{best} = b) = \frac{\exp(-\beta_c)} {\exp(-\beta_a) + \exp(-\beta_c) + \exp(-\beta_d)}. \]

The utilities are only identified up to an additive constant, so I set \(\beta_1 = 0\) and estimate \(\beta_2, \ldots, \beta_{10}\).

Code 
choices <- maxdiff |>
  arrange(`Record ID`, Task, Position) |>
  group_by(`Record ID`, Task) |>
  summarize(
    items = list(Item),
    best = Item[Response == 1][1],
    worst = Item[Response == -1][1],
    .groups = "drop"
  )

log_sum_exp <- function(x) {
  m <- max(x)
  m + log(sum(exp(x - m)))
}

ll <- function(theta, choices_df = choices) {
  beta <- c(0, theta)
  total <- 0

  for (i in seq_len(nrow(choices_df))) {
    shown <- choices_df$items[[i]]
    best_item <- choices_df$best[i]
    worst_item <- choices_df$worst[i]

    total <- total +
      beta[best_item] - log_sum_exp(beta[shown])

    remaining <- shown[shown != best_item]
    total <- total +
      (-beta[worst_item]) - log_sum_exp(-beta[remaining])
  }

  total
}

5 MNL via Maximum Likelihood

The log-likelihood sums the best-pick and worst-pick log probabilities across tasks:

\[ \ell(\boldsymbol{\beta}) = \sum_{\text{tasks}} \left[ \beta_{j_b^*} - \log \sum_{j \in \text{shown}} \exp(\beta_j) - \beta_{j_w^*} - \log \sum_{j \in \text{shown} \setminus \{j_b^*\}} \exp(-\beta_j) \right]. \]

6 MNL via Bayesian Estimation

The Bayesian model uses the same likelihood but adds a weakly informative prior:

\[ \boldsymbol{\beta} \sim N(\boldsymbol{0}, 10I). \]

I use a random-walk Metropolis-Hastings sampler. The proposal adds normal noise to the current vector of 9 free coefficients. I tune the proposal standard deviation so the acceptance rate is in a reasonable range.

Code 
log_post <- function(theta) {
  ll(theta) + sum(dnorm(theta, mean = 0, sd = sqrt(10), log = TRUE))
}

mh <- function(beta0, n_iter, step) {
  K <- length(beta0)
  draws <- matrix(NA_real_, nrow = n_iter, ncol = K)
  beta <- beta0
  lp <- log_post(beta)
  accept <- 0

  for (t in seq_len(n_iter)) {
    beta_star <- beta + rnorm(K, mean = 0, sd = step)
    lp_star <- log_post(beta_star)

    if (log(runif(1)) < lp_star - lp) {
      beta <- beta_star
      lp <- lp_star
      accept <- accept + 1
    }

    draws[t, ] <- beta
  }

  colnames(draws) <- paste0("beta_", 2:10)
  list(draws = draws, accept_rate = accept / n_iter)
}

set.seed(495)
tuning_grid <- c(0.05, 0.08, 0.10)
tuning_results <- bind_rows(lapply(tuning_grid, function(step) {
  tuned <- mh(mle_fit$par, n_iter = 3000, step = step)
  tibble(step = step, acceptance_rate = tuned$accept_rate)
}))

Marketing Analytics is the strongest preference by a wide margin, while Analytics Consulting, Marketing/Finance/Operations, and AI Math/Programming/Analytics are near the bottom. The place where I would still be cautious is the middle of the ranking: SQL, Capstone, Large Data, and Customer Analytics are closer together than the top-versus-bottom contrast, so small changes in the sample or model could plausibly reorder some of them.

The MNL model adds value because it models the actual choice process. It uses the full set of alternatives shown on each task, so every item shown contributes information even when it was not selected. The Bayesian version adds value because uncertainty for derived quantities, such as shares of preference, is easy to compute: I transform every posterior draw into shares and then summarize those transformed draws.

8 Discussion

Substantively, this survey suggests that MSBA students are especially enthusiastic about Marketing Analytics. Business Analytics, Customer Analytics, and Large Data also perform well, while Analytics Consulting and the broad Marketing/Finance/Operations summer class are less preferred in this sample. I would be careful not to treat the middle ranks as precise, because many of those classes have overlapping uncertainty intervals.

Methodologically, I would use the counts analysis for a quick descriptive dashboard. It is transparent and easy to explain. I would use the MLE MNL model when I need a formal model with point estimates and standard errors. I would use the Bayesian MNL model when I care about uncertainty in shares, simulations, or future model extensions such as individual-level preference heterogeneity.

The main caveat is that this was a self-selected survey sample of MSBA students, so the results may not generalize to every student or future cohort. Preferences could also be affected by current standing in the program, prior coursework, professor familiarity, or the order in which items appeared. With more time, I would extend this model hierarchically so that it estimates both the average ranking and how much individual students differ from that average.
